# order-entry-bot

线下门店订单自动录入伯俊 POS 客户端

## 目标

给定一份类似 `docs/orders.xlsx` 的订单明细表，在 Windows 电脑上自动打开并操作`伯俊 POS 客户端`，逐单完成商品条码录入、订单实收价修改、收银确认和后续结果校验。

最终交付物倾向于：

- 一个 Windows 可运行的小工具或 `.exe`
- 支持查询导入订单让其自动录入的记录
- 支持导入外部的订单 Excel
- 支持开始、暂停、继续、停止
- 支持记录每个订单的成功/失败日志
- 支持录单后打开浏览器查询录单结果
- 失败时保留订单号、失败步骤、错误信息和截图，方便人工处理后继续

## 样例 Excel 结构

当前样例文件：`docs/orders.xlsx`

字段：

| 字段 | 说明 |
| --- | --- |
| 订单号 | 每个订单第一行有值，后续商品行为空时继承上一行订单号 |
| 订单实收 | 每个订单第一行有值，作为 `总额折扣` 弹窗中 `特价` 的订单总金额 |
| 商品总数 | 当前仅用于校验，不参与 POS 输入 |
| 支付方式 | 暂不使用，POS 走默认支付方式 |
| 条码 | 需要输入到 POS 条码输入区域 |
| 数量 | 商品数量，数量为 `1` 时使用 POS 默认值；数量大于 `1` 时需要定位该商品条码记录中的数量输入框并修改 |
| 尺码/颜色 | 暂不使用，仅作为人工排查参考 |
| 商品实收 | 暂不使用，仅作为人工排查参考 |

订单日期规则：

- Excel 没有单独日期列
- 使用 `订单号` 前 8 位作为订单日期
- 例如 `20260706004` 对应日期 `2026-07-06`

## POS 操作流程

首次启动：

1. 打开桌面上的伯俊 POS 客户端。
2. 用户名和密码已经保存或已填写。
3. 点击登录，进入主界面。
4. 点击 `收银台`，进入收银台首页。

每个订单：

1. 在收银台界面找到`单据日期`字样后面的日期，日期默认展示的当前时间的日期。
2. 日期控件是下拉选择框，将日期选择为订单号前 8 位对应的日期。
3. 逐个录入该订单下的商品：
   - 复制商品条码到条码输入区域
   - 回车
   - 如果该商品条码对应的 Excel `数量` 为 `1`，无需修改数量，因为 POS 默认数量就是 `1`
   - 如果该商品条码对应的 Excel `数量` 大于 `1`，找到该商品条码记录中的数量输入框，修改为 Excel 的 `数量`
   - 修改数量后按回车，数量即更新成功
4. 订单内所有商品录入完成后，在商品列表表头行最前面勾选，选中所有商品；
5. 按 `F9`或者找到底部`总额折扣`点击，弹出修改订单总价窗口。
6. 在修改总额折扣弹窗中点选 `特价`。
7. 输入 Excel 的 `订单实收` 作为订单总金额。订单的实收金额支持为`0`的情况
8. 修改完订单总额后，点击`确定`闭改价框。
9. 点击右下角的 `收银` 或者按下`F5`。
10. 在弹出的会员输入框中点击 `取消`。
11. 在出现的收银界面，按第一次回车，生成订单。如果订单的时候金额是0的话，此时入单已完成，没有后续的操作了。
12. 等待约 `0.5s`。
13. 按第二次回车，调取小票打印。
14. 第二次回车后会弹出 Windows 系统打印框，需要手动关闭。
15. 当前订单完成，POS 回到收银台首页，继续下一单。

录单完成后的结果校验：

1. 打开浏览器访问指定地址。
2. 在页面中查询录单结果。
3. 查询地址、查询条件和判定规则后续补充。

## 推荐技术方案

优先采用 Windows Python 小工具，并最终打包为 `.exe`。

推荐技术栈：

- `Python 3.11+`
- `openpyxl`：读取 Excel
- `pywinauto`：操作 Windows 原生客户端
- `uiautomation` 或 `pywin32`：作为控件识别和操作补充
- `pyinstaller`：打包为 Windows `.exe`
- `tkinter` / `PySide6`：实现简单桌面 UI，后续按复杂度选择
- `logging`：记录运行日志
- `Pillow` / `mss`：失败时截图

### 为什么优先 pywinauto

`pywinauto` 支持两类常见 Windows 自动化后端：

- `win32`：适合传统 Win32、MFC、VB、部分老式客户端
- `uia`：适合 WPF、WinForms、Qt、现代桌面客户端

伯俊 POS 支持 UI Automation。优先使用控件定位，稳定性更好。


### 输入方式

优先使用剪贴板粘贴，而不是逐字符键入。

原因：

- 条码长，逐字符输入更容易受输入法、焦点、延迟影响
- 剪贴板粘贴速度更快
- 粘贴后回车更接近人工操作

商品条码录入后，POS 默认数量为 `1`。当 Excel 中该商品条码对应的 `数量` 为 `1` 时，不需要额外修改数量。

当 Excel 中该商品条码对应的 `数量` 大于 `1` 时，需要找到该商品条码记录中的数量输入框，修改为 Excel 的 `数量`，然后按回车完成更新。

### 改价方式

订单内所有商品录入完成后，需要先点击商品列表头部的全选勾选框，再按 `F9` 或点击底部 `总额折扣` 进入改价弹窗。

改价弹窗中有三个选项，当前业务固定选择 `特价`，随后输入 Excel 的 `订单实收` 作为订单总金额，并点击 `确定` 关闭改价框。

### 打印框处理

录单末尾有两次回车：

- 第一次回车：生成订单
- 第二次回车：调取小票打印

两次回车之间需要等待约 `0.5s`。第二次回车后会弹出 Windows 系统打印框，当前约定为人工手动关闭，程序需要在日志中记录该步骤，并在必要时暂停等待用户处理。

### 焦点确认

每一步关键输入前都要确认当前窗口和控件焦点：

- POS 主窗口是否存在
- 当前是否在收银台页面
- 条码输入框是否可输入
- 数量大于 `1` 时，该商品条码记录中的数量输入框是否可定位
- 总额折扣改价弹窗是否出现
- 会员弹窗是否出现

### 延迟和等待

不要写固定死等待为主，例如 `sleep(3)`。

应优先使用：

- 等待窗口出现
- 等待控件可见
- 等待控件可用
- 等待弹窗关闭
- 两次回车之间等待约 `0.5s`
- 打印框出现后等待人工关闭或人工确认继续
- 超时后截图并记录失败

### 失败处理

任何订单失败时：

1. 停止当前订单后续操作。
2. 记录订单号。
3. 记录失败步骤。
4. 记录异常信息。
5. 截图保存。
6. 在 UI 中提示用户。
7. 用户人工处理后，可选择：
   - 重试当前订单
   - 跳过当前订单
   - 停止全部任务

## 日志设计

建议输出两个文件：

### 运行日志

例如：

```text
logs/run-20260706-153000.log
```

记录详细步骤：

- 程序启动
- Excel 加载成功
- POS 连接成功
- 当前订单号
- 当前商品条码
- 每一步操作结果
- 异常堆栈

### 结果表

例如：

```text
outputs/result-20260706-153000.xlsx
```

字段建议：

| 字段 | 说明 |
| --- | --- |
| 订单号 | 原订单号 |
| 订单日期 | 从订单号前 8 位解析 |
| 订单实收 | Excel 中的订单实收 |
| 商品数量 | 该订单商品行数 |
| 状态 | `成功` / `失败` / `跳过` |
| 失败步骤 | 失败时记录 |
| 失败原因 | 失败时记录 |
| 截图路径 | 失败时记录 |
| 是否已触发打印 | 第二次回车后记录 |
| 是否已校验 | 浏览器查询后记录 |
| 校验结果 | 后续查询规则明确后记录 |
| 开始时间 | 开始录入该订单时间 |
| 结束时间 | 结束该订单时间 |

## 程序模块规划

建议后续实现时按以下模块拆分：

```text
order_entry_bot/
  app.py                  # 桌面 UI 入口
  excel_reader.py          # 读取和校验订单 Excel
  models.py                # Order / OrderItem 数据结构
  pos_driver/
    base.py                # POS 操作接口定义
    pywinauto_driver.py    # pywinauto 实现
    coordinate_driver.py   # 坐标/图片识别 fallback
  browser_verify.py        # 浏览器结果校验
  workflow.py              # 订单录入主流程
  logger.py                # 日志和结果文件
  config.py                # 配置项
  screenshots.py           # 截图工具
```

## UI 配置项

第一版桌面工具建议提供这些配置：

- Excel 文件路径
- POS 程序路径，可选
- 是否自动启动 POS
- 是否需要点击登录
- 每步操作超时时间
- 操作间隔，默认较保守
- 失败时是否自动暂停
- 打印框出现后是否暂停等待人工关闭
- 输出日志目录
- 结果校验地址，后续补充
- 运行模式：
  - 正式录入
  - dry-run，仅解析 Excel 和展示待录订单，不操作 POS

## 本地运行

建议先创建虚拟环境：

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Windows PowerShell：

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

预览订单：

```bash
python -m order_entry_bot.cli preview docs/orders.xlsx
```

dry-run 跑完整流程，不操作 POS：

```bash
python -m order_entry_bot.cli run docs/orders.xlsx --dry-run --output-dir outputs
```

启动桌面 UI：

```bash
python run_app.py
```

生成默认配置：

```bash
python -m order_entry_bot.cli save-config config/local.json
```

## Windows POS 探测

在 Windows 电脑打开伯俊 POS 后，运行：

```powershell
python tools/inspect_pos.py --backend uia --output outputs/pos-control-tree-uia.txt
python tools/inspect_pos.py --backend win32 --output outputs/pos-control-tree-win32.txt
```

探测文件用于确认这些控件是否能通过 UI Automation 定位：

- 登录按钮
- 收银台入口
- 单据日期
- 商品搜索输入框
- 商品列表中的条码行和数量输入框
- 商品列表表头全选
- `总额折扣` / `特价` / `确定`
- `收银` / 会员弹窗 `取消`

如果某些控件无法稳定定位，修改配置文件中的 `pos.points` 坐标。默认坐标基于 `docs/` 下 2880x1800 录屏，程序会按 POS 窗口大小做比例缩放。

## 已确认事项

- 商品数量为 `1` 时无需修改数量，POS 默认数量就是 `1`。
- 商品数量大于 `1` 时，需要找到该商品条码记录中的数量输入框，修改数量并回车更新。
- 改订单总价前必须先选中所有商品。
- 商品列表头部有 `全选` radio，但无法通过快捷键或控件定位触发，需使用坐标或图片识别。
- 按 `F9` 或点击 `总额折扣` 后弹出的改价框内有三个选项，固定点选 `特价`。
- 输入订单总金额后，点击 `确定` 关闭改价框。
- 日期控件是下拉选择框，选择与订单日期相同的日期即可。
- 录单后的第一次回车用于生成订单。
- 录单后的第二次回车用于调取小票打印。
- 第二次回车需要距离第一次约 `0.5s`。
- 第二次回车后会弹出 Windows 系统打印框，目前需要手动关闭。
- 后续录单结果校验方式是打开浏览器访问指定地址并查询结果。
